# herdr-prs Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a Pull requests panel for the Herdr app. It lists two things
next to Files and Changes: the focused repo's open PRs, and the owner's own
open PRs across GitHub, each with its status.

**Architecture:**
- **One new mod, `gh-prs`.** It draws the panel, and with `props.button` the
  tab-bar toggle.
- **A generated layout, `main-prs`.** A script derives it from the current
  `main` by adding one panel child and one button block. No shipped file
  is edited.
- **Pure modules.** All logic (URL parsing, GraphQL query and parsing,
  formatting, state reduction, layout patch) lives in modules that import
  nothing from the host, so `node --test` covers them. Three thin view files
  use `gpui-kit` and `herdr`.

**Tech Stack:**
- Herdr app 0.1.16: gpui-kit mods in JavaScript (ES modules)
- `gh` 2.103, using `gh api graphql`
- Node 24 (`node --test`, no dependencies)
- bash

**Spec:** `docs/superpowers/specs/2026-11-17-herdr-prs-design.md`

## Global Constraints

**Naming**
- Mod folder `mods/gh-prs`.
- Layout `main-prs`.
- Node ids `gh-prs` (stack child), `gh-prs-button` (button block) and
  `tabs-row` (the wrapping row).
- The stack is `panel-body` and the column is `panel`.

**What it must not touch**
- Never edit a shipped file in `~/.config/herdr-app`.
- Never write `keys.json`, `settings.json`, or any `setShared` key.
  `workspace.panels` especially stays untouched.

**Imports**
- Pure modules (`repo.js`, `github.js`, `format.js`, `state.js`,
  `layout-state.js`, `scripts/make-layout.mjs`) import nothing from
  `gpui-kit` or `herdr`.
- Only `main.js`, `button.js` and `panel.js` import those.

**Code style**
- Immutability: never mutate inputs or stored state objects; return new
  objects. Assigning a new value to a View field (`this.state = next`) is
  allowed.
- Mods use no `setTimeout`, never keep a `cx` for later, and animate only
  through `.spin()` / `.frames()` / `.loop()`.

**GitHub calls**
- They happen only while the panel is shown.
- At most 1 request in flight.
- Interval 60 000 ms; `exec` timeout 20 000 ms.
- 30 PRs per list (`first:30`).
- github.com only, through the active `gh` account.
- Pass `gh api` values with `-f`, never `-F`.
- Mine search string exactly:
  `is:pr is:open author:@me archived:false sort:updated-desc`. This is
  verified working on 2026-11-17.

**Process**
- Commits use conventional types (`feat:`, `test:`, `docs:`, `chore:`).
  No `Co-Authored-By` line (owner's rule).
- Every mod change ends with a passing
  `herdr-app check ~/.config/herdr-app/mods/gh-prs`.

## Review Focus

1. **The focused pane has no folder, isn't a git repo, or has only a
   non-GitHub remote** (a mod pane, `~`, a GitLab repo). This repo should
   show a one-line note, and Mine should still load. Pinned in Task 2
   (`resolveRepo` tests).
2. **The network drops or `gh` times out after data has loaded.** The last
   lists should stay, and the header should say "Couldn't refresh". Pinned
   in Task 4 (`applyFetch` tests).
3. **A space on a remote machine.** `git` should run with `on: machine`;
   `gh` should run locally with no `cwd`. Pinned in Task 2 (the fake exec
   records `on`) and Task 3 (`ghArgs` carries no cwd).
4. **`upstream` points to a non-GitHub host while `origin` is GitHub.** It
   should fall back to `origin`. Pinned in Task 2.
5. **Owners or repos that look numeric or have dots and dashes**
   (`1acme/1acme-platform`, `a.b/c.d.git`). They should parse
   exactly and be sent as strings. Pinned in Task 2 (`parseGitHubRemote`)
   and Task 3 (`ghArgs` uses `-f`).

- Produces:
  - `export function parseGitHubRemote(url: string): {owner: string, name: string} | null`
    - It accepts `git@github.com:o/r`, `ssh://git@github.com/o/r` and
      `https://github.com/o/r`, each with an optional trailing `.git` or

      origin` with `{cwd: root, on}`. The first one that parses as GitHub
      wins.
    - If neither parses, it returns `note:"No GitHub remote"`.

### Task 3: `github.js`: query, gh arguments, response parsing, failure kinds

**Files:**
- Create: `mods/gh-prs/github.js`, `test/github.test.js`

**Interfaces:**
- Consumes: the `{owner, name}` shape from Task 2.
- Produces:
  - `export const LIMIT = 30`
  - `export const MINE_QUERY = "is:pr is:open author:@me archived:false sort:updated-desc"`
  - `export function buildQuery(withRepo: boolean): string`
    - It always asks for `viewer{login}` and
      `mine: search(query:$mine, type:ISSUE, first:30){issueCount nodes{...pr}}`.
    - When `withRepo` is true, it also adds
      `$owner:String!, $name:String!` and
      `repository(owner:$owner,name:$name){nameWithOwner pullRequests(states:OPEN, first:30, orderBy:{field:UPDATED_AT, direction:DESC}){totalCount nodes{...pr}}}`.
    - The `pr` fragment is the one listed in the spec, under Data.
  - `export function ghArgs(repo: {owner,name}|null): string[]`. It returns
    `["api","graphql","-f",`query=${buildQuery(!!repo)}`,"-f",`mine=${MINE_QUERY}`]`,
    plus `"-f",`owner=…`,"-f",`name=…`` when a repo is given. It never uses
    `-F`.
  - `PrRow` = `{number, title, url, isDraft, review: string|null, mergeable: string, ci: string|null, updatedAt, branch, author: string|null, repo}`
  - `Section` = `{items: PrRow[], total: number, error: string|null}`
  - `export function parseResponse(stdout: string): {repo: Section|null, mine: Section|null}`
    - Each `errors[]` entry whose `path[0]` is `"repository"` or `"mine"`
      becomes that section's `error`. Its items are then `[]` and its total
      is 0.
    - `repo` is null when the query had no repository block.
    - It throws on invalid JSON.
    - When there is no `data` at all, it throws `Error(errors[0].message)`,
      for example on a bad query or a rate limit.
    - `author` is `node.author?.login ?? null`. Deleted users give null.
  - `export function classifyFailure(failure: Error | {code, stdout, stderr}): {kind: "missing-gh"|"auth"|"network", message: string}`
    - An Error whose message matches `/time(d)?\s?out/i` gives `network`.
      Any other Error gives `missing-gh`.
    - A result whose stderr matches
      `/auth login|not logged in|authentication|HTTP 401/i` gives `auth`.
    - Anything else gives `network`. Its message is the first non-empty line
      of stderr, or "gh exited <code>".
